Gamifikasi Praktikum: VLAN Tower Defense & Memory Overcommit Crisis

Materi praktikum gamifikasi berbasis web ringan untuk mata kuliah Jaringan Komputer, Sistem Operasi Lanjut, dan Komputasi Awan (Cloud Computing). Dirancang agar mahasiswa dapat memahami konsep fundamental tanpa membutuhkan spesifikasi laptop yang berat.

1. Latar Belakang & Tujuan Gamifikasi Praktikum

Dalam praktikum konvensional, mahasiswa kerap menghadapi hambatan teknis seperti keterbatasan hardware saat menjalankan simulator berat (GNS3, EVE-NG, atau membuka beberapa Virtual Machine di VMware Workstation secara bersamaan). Pendekatan gamifikasi ini membagi tantangan ke dalam dua skenario terisolasi yang dapat dijalankan secara instan di web browser atau diintegrasikan ke laboratorium nyata:

Skenario 1: VLAN Tower Defense

Memahami segmentasi Layer 2 (Data Link), enkapsulasi IEEE 802.1Q trunking, dan pencegahan packet leakage antar departemen dalam batas waktu 15 menit.

Skenario 2: Memory Overcommit Crisis

Memahami manajemen resource hypervisor, virtio-ballooning memory reclamation, Kernel Samepage Merging (KSM), dan penanganan insiden Linux Out of Memory (OOM) Killer.

2. Panduan Skenario 1: VLAN Tower Defense

Untuk penerapan langsung pada perangkat lunak Cisco Packet Tracer, dosen atau instruktur dapat membuat Custom Packet Activity (.pka) dengan panduan konfigurasi CLI switch Cisco Catalyst sebagai berikut:

// Tahap 1: Pembuatan VLAN Database
Switch> enable
Switch# configure terminal
Switch(config)# vlan 10
Switch(config-vlan)# name Finance
Switch(config-vlan)# exit
Switch(config)# vlan 20
Switch(config-vlan)# name Engineering
Switch(config-vlan)# exit
// Tahap 2: Konfigurasi Access Ports
Switch(config)# interface range fastEthernet 0/1 - 4
Switch(config-if-range)# switchport mode access
Switch(config-if-range)# switchport access vlan 10
Switch(config-if-range)# exit
Switch(config)# interface range fastEthernet 0/10 - 12
Switch(config-if-range)# switchport mode access
Switch(config-if-range)# switchport access vlan 20
Switch(config-if-range)# exit
// Tahap 3: Konfigurasi 802.1Q Trunk Uplink
Switch(config)# interface gigabitEthernet 0/1
Switch(config-if)# switchport trunk encapsulation dot1q
Switch(config-if)# switchport mode trunk
Switch(config-if)# switchport trunk allowed vlan 10,20
Switch(config-if)# exit
Switch(config)# do show vlan brief
Tantangan Gamifikasi (Misi 15 Menit): Buat skrip traffic generator di Packet Tracer (menggunakan simulation mode complex PDU). Mahasiswa dinyatakan menang jika 100% paket Client A berhasil mencapai Server Finance tanpa satu pun paket masuk ke broadcast domain VLAN 20.

3. Panduan Skenario 2: Memory Overcommit Crisis

Pada lingkungan praktikum Proxmox VE atau VMware ESXi, berikan tantangan kepada tiap kelompok mahasiswa dengan spesifikasi fisik host 16 GB RAM yang menampung 3 Virtual Machine:

// Perintah Konfigurasi virtio-balloon di Proxmox Host CLI
# Konfigurasi VM 101 (Web Nginx): Max 6GB, Min Balloon 1.5GB
qm set 101 --memory 6144 --balloon 1536

# Konfigurasi VM 102 (DB Postgres): Max 10GB, Min Balloon 3GB
qm set 102 --memory 10240 --balloon 3072

# Konfigurasi VM 103 (AI Worker): Max 14GB, Min Balloon 3.5GB
qm set 103 --memory 14336 --balloon 3584
// Mengaktifkan Kernel Samepage Merging (KSM) pada Host Linux
systemctl enable --now ksmtuned
echo 1 > /sys/kernel/mm/ksm/run
# Periksa jumlah memori yang berhasil di-deduplikasi:
cat /sys/kernel/mm/ksm/pages_sharing
// Skrip Stress Test yang Dijalankan di Guest VM
# Menjalankan stress memory worker pada VM 102:
stress-ng --vm 2 --vm-bytes 4G --vm-keep --timeout 300s
Kondisi Kemenangan: Kelompok mahasiswa yang paling cepat mengonfigurasi batas memory ballooning dinamis dan mengaktifkan KSM sehingga ketiga VM dapat menyelesaikan proses stress-test tanpa memicu Kernel Panic OOM adalah pemenangnya.

4. Komparasi Arsitektur: Kubernetes vs Red Hat OpenShift (OCP)

Buka Simulator CLI Dual →

Dalam dunia industri modern, pemahaman mengenai platform kontainer tingkat enterprise adalah kompetensi wajib. Kubernetes (K8s) adalah proyek upstream open-source di bawah naungan Cloud Native Computing Foundation (CNCF), sedangkan Red Hat OpenShift Container Platform (OCP) adalah produk distribusi enterprise komersial yang dibangun di atas Kubernetes.

Vanilla Kubernetes (K8s)
  • Filosofi: "Do-it-Yourself" (DIY). Inti orkestrasi kontainer minimalis.
  • Ingress: Membutuhkan Ingress Controller pihak ketiga (Nginx, Traefik, HAProxy) yang diinstal manual.
  • Keamanan: Secara default permisif. Kontainer diizinkan berjalan sebagai root (UID 0) kecuali jika dibatasi dengan Pod Security Standards (PSS).
  • Build & CI/CD: Tidak memiliki mekanisme build bawaan. Memerlukan tool eksternal seperti Jenkins, GitLab CI, atau GitHub Actions.
  • CLI Tool: kubectl murni.
Red Hat OpenShift (OCP)
  • Filosofi: "Batteries-Included". Solusi full-stack siap produksi untuk enterprise.
  • Ingress: Memiliki objek Route bawaan berbasis HAProxy dengan wildcard DNS otomatis.
  • Keamanan: Sangat ketat (Strict). Secara default memblokir root container melalui Security Context Constraints (SCC).
  • Build & CI/CD: Memiliki fitur Source-to-Image (S2I) dan internal image registry; mampu membangun kontainer langsung dari repository Git via oc new-app.
  • CLI Tool: oc CLI (super-set dari kubectl) yang mendukung context project dan status manajemen.
// Perbandingan Sintaks Perintah Esensial (kubectl vs oc)
// Vanilla Kubernetes kubectl get nodes
kubectl get pods -n my-app
kubectl apply -f ingress.yaml
kubectl config set-context --namespace=my-app
// Red Hat OpenShift oc get nodes
oc project my-app
oc expose service my-svc # Buat Route
oc new-app nodejs:18~https://github.com/repo

5. Rubrik Penilaian Praktikum (Asesmen Kinerja)

Aspek Penilaian Bobot Kriteria Keberhasilan
Konfigurasi VLAN & Trunking 30% VLAN 10 dan 20 terkonfigurasi dengan port access yang tepat; port gi0/1 beroperasi sebagai trunk 802.1Q tanpa kesalahan enkapsulasi.
Integritas Paket (Zero Leakage) 25% 100% paket Finance tersalurkan ke server tujuan; tidak terjadi packet leak ke VLAN Engineering atau kompromi oleh node rogue.
Manajemen Memory Ballooning 25% Pengaturan target virtio-ballooning adaptif terhadap lonjakan beban stress-ng; alokasi memori tidak defisit di bawah batas kerja aktif VM.
Mitigasi Overcommit & OOM 20% KSM aktif dengan deduplikasi efisien; host node Proxmox bertahan di bawah ambang batas OOM-Killer selama simulasi 15 menit penuh.
