Bandingkan bagaimana objek dikonfigurasikan di Kubernetes murni vs OpenShift Enterprise.

Vanilla Kubernetes (Ingress) networking.k8s.io/v1 
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: banking-ingress
  annotations:
    nginx.ingress.kubernetes.io/ssl-redirect: "true"
    cert-manager.io/cluster-issuer: "letsencrypt-prod"
spec:
  ingressClassName: nginx
  rules:
  - host: banking.company.com
    http:
      paths:
      - path: /
        pathType: Prefix
        backend:
          service:
            name: banking-svc
            port:
              number: 8080

Karakteristik: Membutuhkan instalasi Ingress Controller terpisah (seperti Nginx atau Traefik) dan pengelola sertifikat (cert-manager).

Red Hat OpenShift (Route) route.openshift.io/v1 
apiVersion: route.openshift.io/v1
kind: Route
metadata:
  name: banking-route
spec:
  host: banking-prod.apps.ocp.internal
  to:
    kind: Service
    name: banking-svc
  port:
    targetPort: 8080
  tls:
    termination: edge
    insecureEdgeTerminationPolicy: Redirect

Karakteristik: Terintegrasi secara native dengan OpenShift Ingress Router (HAProxy). Mendukung automatic TLS Edge termination tanpa modul pihak ketiga.

Vanilla Kubernetes (Pod Security Standards) v1 / SecurityContext 
apiVersion: v1
kind: Pod
metadata:
  name: secured-pod
spec:
  securityContext:
    runAsNonRoot: true
    runAsUser: 10001
    fsGroup: 2000
  containers:
  - name: app
    image: myrepo/app:1.0
    securityContext:
      allowPrivilegeEscalation: false
      capabilities:
        drop: ["ALL"]

Karakteristik: Developer harus secara manual menuliskan runAsNonRoot atau mengaktifkan label Admission PSS (Privileged, Baseline, Restricted) pada level namespace.

Red Hat OpenShift (Security Context Constraints - SCC) security.openshift.io/v1 
apiVersion: security.openshift.io/v1
kind: SecurityContextConstraints
metadata:
  name: restricted-v2
allowPrivilegedContainer: false
runAsUser:
  type: MustRunAsRange
seLinuxContext:
  type: MustRunAs
readOnlyRootFilesystem: false
supplementalGroups:
  type: RunAsAny

Karakteristik: Secara default, OpenShift menolak eksekusi kontainer sebagai root (UID 0). Setiap project dialokasikan rentang UID unik acak untuk mencegah eskalasi host.

Vanilla Kubernetes (Eksternal CI/CD) Pipeline Eksternal 
# Kubernetes murni tidak memiliki komponen build bawaan.
# Workflow membutuhkan tool eksternal:
1. Developer commit kode ke GitHub / GitLab
2. GitHub Actions / Jenkins menjalankan docker build
3. Push image ke Harbor / Docker Hub / AWS ECR
4. Menjalankan 'kubectl apply -f deployment.yaml'

Karakteristik: Fleksibel namun mengharuskan tim DevOps merakit dan merawat seluruh rantai build & registry image secara mandiri.

Red Hat OpenShift (Source-to-Image / BuildConfig) build.openshift.io/v1 
apiVersion: build.openshift.io/v1
kind: BuildConfig
metadata:
  name: fintech-api
spec:
  source:
    git:
      uri: https://github.com/app/fintech.git
  strategy:
    sourceStrategy:
      from:
        kind: ImageStreamTag
        name: 'nodejs:18'
  output:
    to:
      kind: ImageStreamTag
      name: 'fintech-api:latest'

Karakteristik: Fitur Source-to-Image (S2I) mengompilasi kode sumber langsung menjadi kontainer di dalam cluster tanpa perlu menulis Dockerfile secara manual.

Matriks Perbandingan Mendalam: Kubernetes vs OpenShift

Analisis komprehensif untuk bahan kajian praktikum, sertifikasi CKA/CKAD vs EX280 (Red Hat DO180/DO280).

Dimensi Komparasi Vanilla Kubernetes (K8s) Red Hat OpenShift (OCP) Implikasi Nyata di Industri
Kategori & Lisensi Open Source murni (Apache 2.0) di bawah CNCF. Distribusi Enterprise komersial (Red Hat) berbasis OKD. K8s gratis tanpa biaya lisensi; OpenShift menggunakan model langganan berbayar per core/socket dengan SLA 24/7.
Sistem Operasi Host Bebas (Ubuntu, Debian, RHEL, Rocky, CentOS). Wajib RHCOS (Red Hat Enterprise Linux CoreOS) immutable. OpenShift melakukan upgrade OS node secara otomatis bersamaan dengan upgrade cluster.
Postur Keamanan Default Permisif secara default; kontainer dapat berjalan sebagai root jika tidak dibatasi. Strict (Ketat); root container diblokir oleh Security Context Constraints (SCC). Sangat krusial untuk sektor perbankan & fintech yang mewajibkan kepatuhan PCI-DSS dan ISO 27001.
Routing & Ingress Layer 7 Harus menginstal Ingress Controller manual (Nginx, Traefik, Kong). Tersedia langsung (Built-in) via Route berbasis HAProxy. OpenShift langsung memberikan subdomain wildcard seperti *.apps.ocp.internal tanpa konfigurasi DNS eksternal yang rumit.
Image Registry & CI/CD Memerlukan external registry (Harbor, DockerHub) dan CI/CD eksternal. Internal registry bawaan, Source-to-Image (S2I), dan OpenShift Pipelines (Tekton). Developer dapat langsung menjalankan oc new-app dari URL repositori Git tanpa membuat Dockerfile.
Antarmuka Web (UI/UX) Kubernetes Dashboard sederhana (sering dinonaktifkan di production). Web Console Enterprise kaya fitur dengan perspektif Administrator & Developer. Visualisasi topologi aplikasi grafis bawaan mempermudah monitoring status pod, traffic flow, dan log secara real-time.
CLI & Tooling kubectl murni. oc CLI (super-set dari kubectl). Semua perintah kubectl dapat dijalankan menggunakan oc, tetapi oc memiliki perintah praktis seperti oc project dan oc status.
